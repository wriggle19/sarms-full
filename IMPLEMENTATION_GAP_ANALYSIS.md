## 1. Security

### 1.1 Credentials in tracked files
**Status: PARTIAL**
- `SYSTEM_STATUS_AND_REVERT.md` (tracked) contains `sarms:sarms` DB password, `ChangeMe123!` seed password, and `local-dev-secret` JWT hint.
- `sarms-api/README.md` and `sarms-web/README.md` (tracked) contain `ChangeMe123!`.
- `.env` files are correctly gitignored.
- `sarms-api/.env.example` does not exist — operators have no template.
- **Fix required:** Redact real credentials from docs; create `.env.example`; add note that seed passwords must be changed.

### 1.2 JWT fallback secret
**Status: BROKEN**
- `auth.module.ts` and `jwt.strategy.ts` both fall back to `'change-me-in-env'` if `JWT_SECRET` is unset.
- In production this means a missing env var silently uses a known-public secret.
- **Fix required:** Throw at startup if `JWT_SECRET` is not set in production.

### 1.3 Docker Compose default credentials
**Status: BROKEN**
- `docker-compose.yml` hardcodes `POSTGRES_PASSWORD: sarms` and `JWT_SECRET: "change-this-to-a-long-random-string"`.
- These are committed and will be used verbatim if an operator runs `docker compose up` without overriding.
- **Fix required:** Move secrets to a `.env` file referenced by compose; document this clearly.

### 1.4 Password hashing
**Status: COMPLETE**
- bcrypt with cost 12 throughout. Acceptable for a school system.

### 1.5 Rate limiting
**Status: COMPLETE**
- ThrottlerGuard global (200/min), login endpoint 5/min via `@Throttle`.

### 1.6 RBAC / PermissionGuard
**Status: PARTIAL**
- `PermissionGuard` correctly reads permissions from JWT and enforces them.
- **Gap 1:** `GET /requests/mine` has no `@RequirePermission` — any authenticated user can call it (acceptable by design, but undocumented).
- **Gap 2:** `PATCH /requests/:id/cancel` has no `@RequirePermission` — any authenticated user can attempt to cancel any request (the service checks ownership, so IDOR is prevented, but the missing guard is a code smell).
- **Gap 3:** `GET /attachments/:id` (download) uses `JwtAuthGuard` only, no `PermissionGuard`. The service does a module-level permission check, which is correct, but it is not visible at the controller layer.
- **Gap 4:** `GET /attachments` (list) has no permission check at all — any authenticated user can list attachments for any entity.
- **Gap 5:** Finance data (`originalCost`, `bookValue`, etc.) is returned in `GET /assets` and `GET /assets/:id` responses to any user with `assets.view`. There is no field-level filtering.

### 1.7 CORS
**Status: COMPLETE**
- Restricted to `CORS_ORIGIN` env var, defaults to `localhost:5173`.

### 1.8 Helmet / secure headers
**Status: COMPLETE**
- `helmet()` applied in `main.ts`.

### 1.9 Input validation
**Status: COMPLETE**
- `ValidationPipe` with `whitelist: true, forbidNonWhitelisted: true` globally applied.

### 1.10 File upload security
**Status: COMPLETE**
- MIME allowlist, 10 MB cap, extension blocklist, random disk names in `attachments.service.ts`.

### 1.11 Path traversal
**Status: COMPLETE**
- Multer diskStorage writes to a fixed directory; download uses stored path from DB, not user input.

### 1.12 SQL injection
**Status: COMPLETE**
- Prisma ORM with parameterised queries throughout. No raw SQL.

### 1.13 XSS
**Status: COMPLETE**
- React frontend escapes by default. API returns JSON, not HTML.

### 1.14 Password reset
**Status: COMPLETE**
- SHA-256 hashed token, single-use, 60-minute expiry, account-enumeration-safe response.

### 4.2 Self-approval prevention
**Status: COMPLETE**

### 4.3 Approval workflow engine
**Status: COMPLETE**
- Configurable multi-step workflows; LINE_MANAGER/DEPARTMENT_HEAD/ROLE/SPECIFIC_USER approver types.

### 4.4 Concurrent issuance prevention
**Status: COMPLETE**
- Serializable transaction in `issuance.service.ts` marks request ISSUED before custody.issue() runs.

### 4.5 Pending queue accuracy
**Status: PARTIAL**
- `pendingFor()` iterates all PENDING_APPROVAL requests in application code (N+1 queries for large queues).
- **Not broken** for a school with <500 requests, but will degrade at scale.

### 4.6 Request edit after submission
**Status: MISSING**
- No `PATCH /requests/:id` endpoint. Users cannot edit a DRAFT or CHANGES_REQUESTED request.
- **Fix required:** Add update endpoint restricted to DRAFT/CHANGES_REQUESTED status.
